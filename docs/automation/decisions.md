# Autopilot decisions

Non-obvious choices made without asking, with the reason and the alternative. Newest last.

| Date | Decision | Why | Alternative |
|---|---|---|---|
| 2026-11-10 | Codex runs unattended via `codex exec --approve-for-me` (workspace-write sandbox with network) in a sibling git worktree `../TasksNearMe-ui`, on port 3100, one ticket at a time | Claude and Codex can work in parallel without editing the same files or fighting over port 3000; the sandbox limits what Codex can touch | `--dangerously-bypass-approvals-and-sandbox` (no sandbox; rejected as unnecessary risk) |
| 2026-11-10 | Claude updates `docs/ui/progress.md`; Codex writes only its handoff file | Avoids merge conflicts between the two worktrees | Codex edits its own progress row (caused conflicts in parallel runs) |
| 2026-11-10 | The autopilot commits locally to `main` after green checks; never pushes | The user asked for fully autonomous building; local commits are safe checkpoints | Ask before each commit (would stall the run) |
| 2026-11-11 | Local database: Docker `postgis/postgis:17-3.5` on port 54329, with a separate `tasksnearme_test` database | Docker Desktop was installed and started without interaction; matches production (Postgres + PostGIS) | PGlite or embedded Postgres (no PostGIS) |
| 2026-11-11 | Text primary keys with type prefixes (`usr_…`, `tsk_…`) instead of UUIDv7 | Readable in logs and fixtures; Better Auth uses text ids too | UUIDv7 columns |
| 2026-11-11 | A market is a center + radius; an area is a named center point (a location's area = nearest center) | Enough for one city; avoids drawing polygons now | Area polygons (blueprint 08); can be added later without changing callers |
| 2026-11-11 | DB integration tests run with `npm run test:db`, separate from `npm run check` | Codex's worktree and machines without Docker can still run `check` | Mixing DB tests into `check` |
| 2026-11-11 | Auth: Better Auth with email one-time codes (6 digits, 10 min, 3 attempts), Drizzle adapter, prefixed ids (`usr_`, `ses_`, `acc_`, `ver_`). Until an email provider key exists, mail goes to `dev_outbox_messages` (shown at `/dev/outbox`) | Passwordless sign-in as in the blueprint; no provider key is available (see `blocked.md`) | Magic links; Auth.js |
| 2026-11-11 | Staff two-step check: outside production, code `123456` is accepted and recorded per session in `staff_session_checks`. Real TOTP enrollment comes with the admin staff screens (UI-020) | Gates `/admin` with its final shape now | No staff check until TOTP exists |
| 2026-11-11 | `/dev/sign-in` signs in as a seeded person through the real code flow, with the code created on the server; sign-ins for the same email run one after another | Manual and e2e testing without email; parallel Playwright projects were replacing each other's codes | Reading codes from the dev outbox (raced under parallel tests) |
| 2026-11-11 | `src/proxy.ts` makes an optimistic session-cookie check on `/app/**` (real 307 to sign-in, `next` kept); the layouts do the real check. `/admin` is not matched and shows not-found to non-staff | Real redirect for signed-out visitors; no hint that `/admin` exists | Layout redirects only (streamed, client-side) |
| 2026-11-11 | Next's dev-only "Could not validate `instant`" warnings on gated layouts are expected and left alone | They appear only when the request is meant to be refused (`notFound()` / `redirect()`) | `export const instant = false` on the gated layouts |
| 2026-11-11 | Public marketing data is cached with `"use cache"` (tagged `market:<slug>`), and the pages prerender at build time, so `next build` needs the database | Fast, indexable pages; one cache tag to refresh after admin changes | Render on every request (slower; no static shell) |
| 2026-11-11 | Unknown market or category slugs show the not-found page with `noindex` (status 200, because the response is already streaming) | ISR with Cache Components serves the App Shell first; a real 404 would need a proxy lookup | `dynamicParams = false` (new markets would need a redeploy) |
| 2026-11-11 | The fee engine is pure functions over integer cents (`modules/payments/fees`), tested against every canonical example. Pricing and become-a-helper pages are built from it plus the published market policy | One source of truth for money on every screen | Hard-coded examples |
| 2026-11-11 | Reward program terms are constants (`modules/rewards/programs`) switched by the `reward.*` flags until the rewards module (Phase 7). Founding spots claimed = helpers given a founding number in the market | Matches blueprint 05; no reward tables yet | Reward tables now |
| 2026-11-11 | Playwright e2e: 4 workers and a 15 s expect timeout | One dev server compiles routes on demand; 10+ workers made sign-in flows time out | Run e2e against a production build (needs a test-only sign-in) |
| 2026-11-11 | Help and legal content are Markdown files in `content/`, parsed by a small subset parser (`modules/content/markdown`) into typed `ContentBlock`s; a test checks every file parses and every internal link resolves | Editable text, no HTML injection, no Markdown dependency | A CMS, or MDX (needs a loader and lets JSX into content) |
| 2026-11-11 | Legal documents ship as `Draft 0.1` with a not-in-effect banner and `noindex`; sign-up records `terms_version = draft-0.1` | No lawyer-reviewed text yet (blocked.md) | Leave the legal pages empty |
| 2026-11-11 | Per-IP rate limits apply only when the client address is known and not local (`X-Forwarded-For`); per-email and per-user limits always apply | Local and e2e requests share one loopback address and tripped each other's limits | A higher IP limit (would still collide in local runs) |
| 2026-11-11 | Better Auth reads the session from headers rebuilt from the current cookie jar (`authRequestHeaders`) | After sign-in in a Server Action, `headers()` still carries the old Cookie header, so `refresh()` rendered the signed-out step | Redirect to a fresh request after every step |
| 2026-11-11 | Sign-in steps are decided on the server (`resolveSignInStep`); the phone step appears only when the destination needs it (posting, offers, booking) | Blueprint 02 §1 ("phone verification when needed"); keeps flow logic out of the UI | Ask every new account for a phone |
| 2026-11-11 | Partial Prefetching is per segment (`prefetch = 'partial'` on the `/app` and `/admin` layouts), not global | Globally it embedded a second full payload in every public page that has a dynamic hole (the account area): production home 323 KB, versus 197 KB per segment | Global flag (instant public navigations, double payload) |
| 2026-11-11 | Public dynamic routes await `params` outside Suspense, with `generateStaticParams`. Unknown slugs return a real 404 (supersedes the soft-404 row above) | The recommended pattern without global Partial Prefetching: each URL gets its own cached render | Await inside Suspense (soft 404s, shared fallback) |
| 2026-11-11 | `PublicShell` receives the viewer as a promise (UI-005); the public layout has no Suspense wrapper | The page body renders once; only the account area waits for the session | Suspense around the whole shell (sent each page twice) |
| 2026-11-11 | When a contract adds an error code, Claude adds placeholder copy for it in `messages/en/ui` in the same commit, and the next ticket asks Codex to review the wording | Codex's tests require copy for every code, so new codes would otherwise break `main` | Hold contract changes until Codex is free (stalls the backend) |
| 2026-11-11 | Exact task addresses are stored as AES-256-GCM JSON in `task_locations.address_enc`; tasks keep only the area and a deterministically fuzzed public point (≤ 300 m from the area center) | Blueprint 06 privacy; the public point never leads to the house | PostGIS points of the real address |
| 2026-11-11 | Prohibited-task checks are whole-word phrase matches against global phrases plus category keywords. Moving keywords are narrowed ("your truck", not "truck") | Loading a rented truck is in scope; transport in the helper's vehicle isn't (blueprint 01 §6.1) | Plain substring matching (blocked ordinary moving tasks) |
| 2026-11-11 | Seeded open tasks get windows relative to the seed date (market time) | The board always has upcoming tasks in dev and e2e | Fixed dates (would expire) |
