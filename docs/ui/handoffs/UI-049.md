# UI-049 handoff: the email preferences page

Built by **Claude** while Codex is out (owner request: "implement email related all features").

1. **Built:**
   - `src/ui/screens/account/email-unsubscribe-screen.tsx` (`EmailUnsubscribeScreen`): the page behind the unsubscribe link in a notification email, without signing in. Four states: asks first ("Stop offer emails?", Unsubscribe), done (with "Turn them back on"), locked (booking and payment emails can't be turned off), and a link that doesn't work. Each links to the account's notification settings.
   - Previews: `screen-email-unsubscribe/{confirm,unsubscribed,locked,invalid}` in the public shell.
   - Tests: `email-unsubscribe-screen.test.tsx` (4).
   - Staff person page: the delivery reason `email_suppressed` has copy ("Their email bounced or was marked as spam").
2. **Contracts used:** `EmailUnsubscribePageData`, `EmailUnsubscribeHandlers`, `DELIVERY_REASONS`.
3. **Message namespaces:** `account.unsubscribe`, `account.previews.unsubscribe*`, `adminUser.deliveryReasons.email_suppressed`.
4. **Dependencies added:** none.
5. **Contract requests:** none.
6. **Known gaps or follow-ups:** the page has no route helper in `routes` yet (the email links are built on the server); the account page could show when an address is suppressed and let the person ask to try again.
7. **Previews to review first:** `screen-email-unsubscribe/confirm` (phone first).
